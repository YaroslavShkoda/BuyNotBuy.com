# Инварианты проекта

Конституция. Не список пожеланий: у каждого пункта указан код, который его
обеспечивает, и — главное — честная пометка, **обеспечен он или только
заявлен**.

Эта колонка существует потому, что проект уже семь раз записал утверждение,
которое опроверг его же выход. Формулировка без привязки к исполняемому месту
не стоит ничего: `fillPrice` был «пессимистичным» и подавал лонгу лучшую
половину каждого бара. Ниже такого быть не должно — либо инвариант чем-то
обеспечен, либо в последней колонке написано «только заявлен», и это означает
ровно то, что написано.

Проверить, что таблица не расходится с кодом, можно так:

```
node --env-file=.env --import=tsx src/backend/research/architecture-lint.cli.ts
node --env-file=.env --import=tsx src/backend/research/dependency-graph.cli.ts
npx vitest run
```

## 1. Будущее не попадает в решение

| | |
|---|---|
| **Запрещает** | правилу видеть бар, который ещё не закрыт, или значение на баре не последнем |
| **Обеспечен** | `backtest/point-in-time.ts` — `computeSignalAt(candles, index)`; `StrategyContext` не содержит индекса |
| **Чем** | контракт стратегии: `{ candles, price }`. Индекса нет физически, поэтому «спросить прошлый бар» невыразимо |
| **Статус** | обеспечен |

Это единственный инвариант, ради которого в C3 пришлось оставить стенд
квадратичным. Линейный стенд означает индекс в контракте, а индекс в контракте
означает утечку. **Ускорение здесь невозможно по построению — и это цена, а не
долг.**

## 2. Модель исполнения выбирает тот, кто торгует

| | |
|---|---|
| **Запрещает** | модели заполнения выбирать цену по стороне сделки |
| **Обеспечен** | `backtest/execution.ts` — `isBuying = (side === 1) === isEntry`, по умолчанию `next_open` |
| **Чем** | тест, сверяющий заполнение с направлением; `intrabar` живёт под своим именем как верхняя граница убытка |
| **Статус** | обеспечен |

История этого пункта — в коммите `4fb4a39`. Один знак в выражении стоил 43
пункта дохода на одном и том же наборе сделок.

| **Обеспечен** | `market/candle-validation.ts` — `assertCandleSeries`, `findCandleSeriesIssues` |
| **Чем** | проверка непрерывности и полноты; восемь дней в фикстуре отбрасываются здесь же |

## 4. Окно не перечитывают

| | |
|---|---|
| **Запрещает** | выбрать вопрос после того, как ответ увиден |
| **Обеспечен** | `research/holdout-protocol.ts`; миграция 14, `holdout_verdict` с `CHECK (id = 1)` |
| **Чем** | закрытое множество метрик, отпечаток протокола, вердикт как весь выход, одна строка таблицы навсегда |
| **Статус** | обеспечен частично — и это написано, а не сглажено |

Не мешает открыть бары дважды: фикстура в репозитории. Мешает выбрать метрику
после. Второе и было целью.

## 5. Идентичность конфигурации не теряется

| **Статус** | обеспечен |

## 6. Один активный конфиг стратегии

| | |
|---|---|
| **Запрещает** | две версии одной конфигурации быть одновременно активными |
| **Обеспечен** | частичный уникальный индекс по `config_hash` |
| **Статус** | обеспечен |

## 7. Статус версии — из закрытого множества

| | |
|---|---|
| **Запрещает** | значение статуса, которого никто не обрабатывает |
| **Обеспечен** | `CHECK (status IN ('draft', 'approved', 'retired'))` |
| **Статус** | обеспечен |

28 ограничений `CHECK` на 16 таблиц. Это самый надёжный класс инварианта в
проекте: база отказывает сама.

## 8. Продвижение в бой идёт по порядку

| | |
|---|---|
| **Запрещает** | кандидата, прошедшего только бэктест, считать готовым к бою |
| **Обеспечен** | **только заявлен** |
| **Где заявлено** | `strategies/registry.ts` — комментарий описывает порядок candidate → walk-forward → shadow → approval → production |
| **Что обеспечено на деле** | `FALLBACK_MODE` по умолчанию `shadow`; стратегия в тени по умолчанию |

**Это самое слабое место конституции.** Порядок описан в комментарии, а не в
типе. `Status = 'draft' | 'approved' | 'retired'` не выражает «прошёл
walk-forward» и «был в тени», потому что это не свойство версии, а её
истории. Пока это так, «требует одобрения» остаётся правилом, который помнят.

## 9. Атрибуция провайдера не теряется

| | |
|---|---|
| **Запрещает** | потерять, с какой площадки пришли бары, по дороге в сигнал |
| **Обеспечен** | **только заявлен** |
| **Что можно проверить сегодня** | PHASE 21 (роадмап). `second-source.ts` показал, что провайдер меняет числа сильнее, чем знаки: +5.74% против +0.45% на одном и том же правиле |
| **Статус** | не обеспечен |

## 10. Идентичность актива обязательна

| | |
|---|---|
| **Запрещает** | запись, не принадлежащую однозначно конкретному рынку |
| **Обеспечен** | **не обеспечен, и это главное, что предстоит** |
| **Что известно** | `architecture-lint` находит **два** места, где домен решает, что он работает с BTC: `api/routes/health.ts:63` и `observability/health.registry.ts:230` |
| **Статус** | заявлен роадмапом (PHASE 1, PHASE 22), в коде отсутствует |

Два, а не сто десять. Остальные упоминания — комментарии, где записано, что
именно измерялось; они остаются, потому что это находки, а не решения.

## 11. Исследование не импортирует обратно в производство

| | |
|---|---|
| **Запрещает** | production-модулю тянуть `research` |
| **Обеспечен** | `dependency-graph.ts`: `research` — составляющий слой, но ни один другой слой не объявлен с доступом к нему. Проверено: **0** рёбер между слоями ведут в `research` |
| **Статус** | обеспечен |

Именно этим дефектом модуль получает модель исполнения, которую не выбирал.

## 12. Индикатор не ходит в базу

| | |
|---|---|
| **Запрещает** | `indicators → db` |
| **Обеспечен** | **не обеспечен** |
| **Где нарушено** | `indicators/performance/indicator-vote.repository.ts:2`, `indicator-performance.service.ts:9` → `history/` |
| **Статус** | нарушено по построению, а не по ошибке: репозитории лежат в папках доменов |

Решение — не запретить импорт, а перенести репозитории (PHASE 5). Пока они
лежат рядом с логикой, правило нельзя включить, не сломав сборку.

## 13. Контракт не зависит от реализации

| | |
|---|---|
| **Запрещает** | `types` импортировать что-либо, кроме листьев |
| **Обеспечен** | **не обеспечен** |
| **Где нарушено** | `types/analysis.ts:1 → indicators/indicator.service.ts`, `:2 → signals/signal.types.ts` |
| **Статус** | нарушено |

**`MarketAnalysis` — это замороженный контракт, который читает фронтенд, и он
импортирует индикаторы и сигналы.** Нижний слой зависит от двух средних,
значит контракт движется вместе с реализацией, и никто не принимал решения его
двигать. Frontend при этом менять нельзя — значит, чинить надо здесь.

## 14. Тесты не ходят в сеть

| | |
|---|---|
| **Запрещает** | сетевой запрос во время теста |
| **Обеспечен** | `test-support/no-network.ts`; в `vitest.config.mts` он идёт **до** любой заглушки `fetch` |
| **Статус** | обеспечен |

Порядок записан в конфиге намеренно: заглушка, установленная поверх
сторожа, тихо открыла бы сеть обратно.

## 15. Каждый тест — своя схема

| | |
|---|---|
| **Запрещает** | тестам делить состояние базы |
| **Обеспечен** | `test-support/test-database.ts` в `beforeAll` каждого файла |
| **Статус** | обеспечен |

Цена известна и принята: без базы не проходит **ни один** тест, включая
исследовательские. Зато ни один из них не может стать причиной другого.

## 16. Схема базы не новее кода

| **Запрещает** | приложению работать против схемы, которую он не понимает |
