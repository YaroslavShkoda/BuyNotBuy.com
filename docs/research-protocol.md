## Фиксируем вопрос до чтения новых исходов

Четыре отдельные серии: Binance/Bitget × BTCUSDT/ETHUSDT, часовые закрытые бары,
консенсус EMA300/Stochastic100/Momentum100. Для каждого запуска записывать SHA
кода, strategy fingerprint из существующего `fingerprintStrategy(market)`,
периоды, диагностический quality score (в текущем движке он автоматически
не ветирует опубликованный сигнал), источник и hash упорядоченных OHLCV. Изменение
параметров, протокола или семейства гипотез открывает новую версию и будущее окно;
не заменяет предыдущий результат. Алгоритмы, которым подбирали параметры на
имеющихся CSV, не получают ретроспективного статуса «предзарегистрированы».

Первичная метрика — средняя дневная разница net log returns стратегии и
компаратора на общем UTC-пересечении закрытых данных. Для каждой серии два
сравнения: buy-and-hold и среднее пяти seeded random стратегий, сопоставленных
по экспозиции **обучающего** окна. Seeds указаны в JSON; подбирать удачные seeds
или экспозицию на test запрещено. Итого 8 сравнений; все публикуются, включая
отрицательные. Нельзя заменить неудачную доходность profit factor после чтения.

Издержки за сторону: taker fee 0.001, slippage 0.0005, half-spread 0.0002;
`next_open`, один и тот же capital/exposure accounting для компараторов.
Нулевые издержки — отдельная описательная sensitivity, не основной результат.
Это плановые допущения, а не подтверждённые комиссии конкретного аккаунта.

Walk-forward: 2160 training bars, 720 test bars, warmup 900, purge 24;
решение после закрытия бара, исполнение на следующем open. Никаких данных test
в параметрах/признаках training. Regime slices и turnover/drawdown публикуются
описательно, без дополнительных незаявленных тестов значимости.

## Объём, неопределённость и остановка

Family alpha максимум 0.05. На каждое из восьми сравнений заранее выделено
0.005, суммарно ≤0.04; используется консервативная Bonferroni-граница.
Плановая power 0.8 для standardized effect δ/σ=0.2. Нормальная аппроксимация
для независимых наблюдений даёт
`ceil(((2.807033768 + 0.841621234) / 0.2)^2) = 333`.
Это нижняя плановая оценка **независимых эффективных дневных блоков**, не 333
часа и не доказательство мощности на зависимом рынке. До проверки зависимости,
распределения и достаточного числа блоков результат INCONCLUSIVE.

После достижения заранее заданного объёма — один фиксированный разбор, без
ежедневного peeking и ранней остановки на первом p<alpha. Для зависимых дневных
разниц использовать moving-block bootstrap с блоком 7 дней, 10000 повторов и
заранее указанными seeds, 99.5% CI; отдельно публиковать sensitivity длины блока
1/14 дней как описательную. Оценку effective sample size и проверку мощности
на train заморозить перед test. Если зависимость не позволяет обосновать 333
эффективных блока, продолжить сбор; не объявлять power только по числу строк.
Не считать bootstrap волшебной гарантией при смене режима.

Исход каждого сравнения: нижняя граница CI >0 — EVIDENCE_OF_EDGE в указанном
scope; верхняя ≤0 — NO_EDGE; пересечение нуля, плохое качество или недостаточный
объём — INCONCLUSIVE. Общая рекомендация EVIDENCE_OF_EDGE возможна лишь при
успехе всех восьми сравнений и независимом review. Ни один исход не является
обещанием будущей доходности.

Калибровка имеет три состояния:

- `not_calibrated`: нет проспективной проверки/неизменённой модели калибровки;
- `insufficient`: данные есть, но недостаточно независимых наблюдений;
- `evidence`: отдельное отображение agreement→эмпирическая частота построено
  только на train, заморожено и прошло будущую проверку с опубликованными CI.

Raw agreement остаётся долей согласия индикаторов. Его 67% не превращаются
в 67% вероятности успеха. Для биновой частоты события (положительная net
доходность за фиксированные 24 часа после next-open) плановый минимум на бин
`ceil(3.227218426² × 0.25 / 0.05²) = 1042` независимых наблюдений при худшем p=0.5
и приблизительной точности ±5 п.п. Бины [0,.25), [.25,.5), [.5,.75), [.75,1]
фиксированы; не сливать тонкие бины после просмотра. Публиковать Wilson CI и
effective counts, не выводить rate пустого бина как ноль. Отдельная calibration
family имеет alpha=0.005, четыре интервала получают alpha=0.00125 каждый
(99.875% CI). Порог1042 уже включает эту поправку и всё ещё требует проверки
независимости и точности Wilson-интервала на фактических данных.

Формулы и допущения: [NIST sample-size planning](https://www.itl.nist.gov/div898/handbook/prc/section2/prc222.htm),
[NIST proportions precision](https://www.itl.nist.gov/div898/handbook/ppc/section3/ppc333.htm),
[NIST Bonferroni](https://itl.nist.gov/div898/handbook/prc/section4/prc473.htm).

## Сбор и воспроизводимость

Использовать существующую ingestion/backfill с проверенной идентичностью серии;
параллельно собирать обе площадки, не переключать одну историческую серию
между ними. Разрывы, повторения, неполные бары, источник/quote и mismatch
фиксировать до оценки; без silent repair. Новый integrity gate описан в
[historical-integrity-gate.md](historical-integrity-gate.md). Реальный сбор
внешнего будущего окна в этой сессии **NOT_STARTED**.

Проверка доступной истории:

```powershell
node --import=tsx src/backend/research/prospective-readiness.cli.ts
```

Полный JSON-результат сохранён в [research-readiness.json](research-readiness.json).
Он содержит SHA-256 каждого CSV и протокола, периоды, gaps, OHLCV sanity и
отдельный prospective eligibility. Все 4 файла — development; 0 eligible future
bars, outcome INCONCLUSIVE, CI=null, calibration=not_calibrated. Yahoo fixture
имеет BTC-USD и полдень UTC; не выдаётся за Binance BTCUSDT или за вторую venue
одинакового инструмента. Часовая Binance-фикстура имеет 7 разрывов, Yahoo — 5;
дневные BTC/ETH Binance без разрывов. Независимая загрузка для подтверждения
источников сейчас не выполнялась.

Readiness CLI **не выполняет** будущий статистический эксперимент и не выдаёт
состояние evidence по достижению числа баров: независимость, calibration и
опубликованная регистрация требуют отдельного доказательства. Новый протокол
готов к review; его публикация и месяцы будущих данных не заменены синтетикой.

перед LF на уровне байтов; BOM, одиночный CR, whitespace и все остальные байты

CLI теперь проверяет отдельный receipt: версию, hash протокола, UTC timestamp,
отсутствие будущего принятия и ссылку на внешнее решение. Отсутствующий/draft
receipt не открывает будущим барам eligibility; ошибочный receipt завершает CLI
с ненулевым exit, без чистого readiness-результата. Для проверки другого receipt:

```powershell
node --import=tsx src/backend/research/prospective-readiness.cli.ts path/to/registration.json
```

Фактическое начало равно `max(earliestCollectionStart, acceptedAt)`. Бар должен
открыться не раньше принятия и полностью закрыться к моменту проверки. Для 1h
первое подходящее открытие — **06:00 UTC 28.10**, закрытие — **07:00 UTC**;
бар 05:00–06:00 не получает статус будущего наблюдения задним числом.

[Новый readiness/2](research-readiness-owner-accepted.json) фиксирует owner acceptance;
[старый readiness/1](research-readiness.json) остаётся неизменённым историческим
снимком до принятия. В существующих development CSV по-прежнему **0** подходящих
будущих баров, calibration `not_calibrated`, исход `INCONCLUSIVE`, CI=null.
Реальный сбор будущего окна **NOT_STARTED**. Принятие не удостоверяет источники,
независимость наблюдений, достаточную мощность, прибыльность или калибровку.

Receipt — проверяемая запись принятого владельцем решения в review процесса,
не криптографическая подпись личности и не публичный реестр предрегистраций.
Параметры/метрика/seeds/издержки/гипотезы не изменены. Любое их изменение требует
новой версии, нового решения и будущего окна; старые результаты не переписываются.
